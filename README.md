# den extensions

The list of extensions [den](https://github.com/patrickiel/den) offers under **Available** in its Extensions view (Ctrl+Shift+X).

Each extension lives in its author's own repository and is installed from that repository's latest GitHub release. This repository only lists them. An extension that isn't listed can still be installed by typing its `owner/repo` in den's Extensions view.

## List your extension

1. Publish it from its own public repository with `release.yml` from den's [`examples/hello-extension`](https://github.com/patrickiel/den/tree/main/examples/hello-extension). Pushing a tag `v<version>` makes a release with `<id>-windows-x86_64.zip` and an `extension.json` that carries the zip's SHA-256.
2. Give it a description in `extension.json`, a `README.md` (den shows it before anyone installs), and ideally an `icon`.
3. Open a pull request that adds one line to [`extensions.json`](extensions.json) and changes nothing else:

   ```json
   { "repo": "you/your-extension" }
   ```

CI then checks your latest release the way den installs it:
- the manifest is valid;
- it's built for an extension API den has;
- the zip is there and `sha256` is set;
- the id isn't taken;
- `repository`, if set, names your repository.

After a maintainer merges your PR, `index.json` is rebuilt and den shows your extension within the hour. New releases show up in den as updates, because the index is rebuilt daily. You don't need another pull request.

## Being listed is not an audit

An extension is native code: it runs inside den with the user's permissions. Maintainers look at what they list, but they can't vouch for every release that follows. den asks before installing anything, and says so.

## How it works

- `extensions.json`: what authors edit.
- `index.json`: generated by [`tools/den-index`](tools/den-index); never edit it by hand. It's what den fetches, and it holds each extension's latest manifest fields plus links to its icon and README.
- `.github/workflows/check.yml`: runs `den-index check` on each pull request. Entries already listed only warn, so one broken release doesn't block other pull requests.
- `.github/workflows/build.yml`: runs `den-index build` when the list changes and daily, and commits `index.json` when it changed.

To run the tools yourself:

```sh
cargo run --manifest-path tools/den-index/Cargo.toml -- check
cargo run --manifest-path tools/den-index/Cargo.toml -- build
```

Removing an entry from `extensions.json` takes the extension off den's Available list. Anyone who installed it keeps it.
